# J1.3 等待与进度、J5.1 升级证据

2026-11-07。本批实现前冻结契约；完成状态和最终数字以 [README](README.md) 为准。改前身份保存在 `artifacts/android-jev-j13-j51-2026-11-07/before.json`。

## 范围与固定判据

- 候选策略升级为 `search-v3`，仍 `calibrated=false`；完成策略 `search-completion-v2` 不变。
- Jev 搜索可选 `loading: { id }`，仅接受同包资源 ID；它是调用方声明的加载标记，不是模型生成的目标。原始树必须证明标记唯一、可见、非密码/输入控件且不可点击。重复或不安全标记硬停止。未声明、不可见或仅有普通候选缺失，不能获得加载等待资格。
- 标记可见时不提供写候选，只允许模型选择等待或升级；仅发送封闭类别 `declared_loading`，不发送原始屏幕文本或查询值。模型选择 wait 但缺少证据时停止 `TASK_WAIT_UNPROVEN`。
- 每任务最多两个等待窗口，每个最长 5000ms、采样间隔 200ms，从接受等待开始计时，包含轨迹及观察耗时；同时受原总截止、观察和八轮决策预算约束。进入第三个窗口停止 `TASK_WAIT_LIMIT`。本批不新增公共预算开关。
- 等待成功要求加载标记消失且合法搜索候选出现；标记消失但候选仍缺失继续消费同一窗口，到期 `TASK_WAIT_TIMEOUT`。完整旧结果、密码框、歧义、已填值丢失和上下文变化仍停止。等待只读、不证明页面稳定或业务完成；返回下一轮重新观察、决策、派发前复核。
- 等待不清零 stale、不清除已执行目标/历史，不重建上下文基线。阶段、上下文及候选身份形成循环键，目标外时钟/标签变化不算进度。已派发动作不因等待失败而重放；最终完成仍使用原有完整谓词与共用五秒窗口。
- J5.1 在 stopped Jev 回执中提供白名单升级证据：任务/阶段/停止原因、原输入引用、固定完成条件、设备/包/动作约束、最近观察与候选关联、已验证回执索引、全部原子回执、消耗和剩余预算。证据是历史快照；明确无续跑授权、实际写前仍需重新检查权限。unknown、取消、身份/策略失败或预算耗尽不变成可恢复升级。
- 完整升级证据使用单独普通轨迹事件；最终 stopped 事件保留原 4096 字节预留。新增最多四条等待事件与一条升级事件，容量测试保持 512 KiB 上限。
- 轨迹头固定声明的加载 ID；每次观察只记录 `matches/visible/safe`，不保存标记文字。升级包记录最后一份加载证据，并区分候选所属观察和最新宿主观察；两者均为历史证据，不能拿旧候选直接执行。
- 本批无主 Agent 回调、RunTask 内 Handoff 续跑或跨调用恢复；这些仍属 J5.2/M5.2。模型/设备均使用离线替身，不向上游发送探针。

## 验收矩阵

覆盖加载后候选出现、标记消失后延迟出现、始终缺失、无加载依据、重复/隐藏/密码标记、目标外变化、循环、等待次数/观察/模型/轮数/总截止预算、等待中的取消与上下文变化、stale 计数保留、已填入不重填。

升级证据覆盖零写升级、部分执行后升级、unknown、模型错误、硬停止、历史候选/新观察关联、输入与自由文本不外泄、调用方契约不可变、最大预算轨迹与终止预留。完成验证、旧 stale 和既有所有权/排干回归同步运行。

## 实现与验证记录

继续使用现有 `androidSearchLoop`、`androidTaskExecutor`、task-port、step-runtime 及轨迹存储。未新增服务容器、调度器或设备 RPC。原始加载证据集中在 task-port，等待状态和语义循环键属于搜索环，回执投影属于执行器，持久化字段校验属于轨迹存储。

原始标记可以没有文字，且可能被展示层剪掉。因此只在原始树证明声明标记唯一可见、安全且布局/上下文完整时允许“零展示控件”的只读加载观察；其它空树/不可信页面仍拒绝。输入角色复用既有角色判定，包含 AutoCompleteTextView，不另写只识别 EditText 的规则。

`escalation` 的 `scope` 是任务约束，`policy=recheck_required` 不代表已经批准后续动作；`budget/counts/remaining` 保留原限额和消耗，已验证回执索引不把“派发过”或 unknown 算成进展。读取剩余时间在取消/截止后可能抛错，报告路径将可用时间记零，不再次启动执行。外层取消仍沿原错误回执返回；已进入执行器的任务在依赖排干后记录内部停止轨迹。

测试分为实际 Service + 原始 XML / 模型替身和虚拟时钟窗口测试。共享目录新增 `waitCases`，旧完成与 stale 夹具保留。固定替身回答证明控制流，不能证明真实模型质量或设备时延。

改前五项失败保存在 [baseline-red.log](../../artifacts/android-jev-j13-j51-2026-11-07/baseline-red.log)。首次扩展专项两项测试预期错误（观察预算低于既有准入下限、把未验证返回动作计入已验证数）保留在 `targeted-r1.log`；修正测试预期，未放宽生产准入或验证判据。收尾补齐声明标记及逐观察白名单证据前的限定回归保留为 `r1-final-*`。
