# J3.1 多屏查找冻结契约

2026-11-07，实现前冻结。基线 search-v6；候选 search-v7 / search-feedback-v3；完成仍 search-completion-v2，calibrated:false。无真实上游请求或真机操作。使用本批改前快照，保留既有脏文件。

## 授权及结构

`searchActions.scroll` 新增可选整数 `maxSwipes`，默认1，上限4；大于1仅接受 `command=Scroll`。每次都是现有原子 Scroll 的一个 swipe，重新观察、调用 Jev、复核策略/fence、独立验证后才可能继续。`ScrollUntil` 仍至多1，保持自身“目标未找到即未验证”的设备原语语义，不把 unknown 改写为可继续进展。不增加八轮、动作、观察、模型或总截止预算，不增加重试或主 Agent 升级次数。

新增局部 `task-scroll-progress.js` 负责内部锚点快照及方向性验证，避免把原始树解析混入决策循环；不另建执行器。普通搜索和未声明多屏的路径保持既有行为。多屏只发生在输入前，并且必须沿声明的同一容器、目标和方向；进入该查找后，不因出现其它搜索控件而离开声明目标。

## 进展判据

先沿用唯一安全容器、上下文和合法目标的检查。指定合法目标可用时，可直接证明查找完成。否则，继续查找必须同时满足：

- 容器身份、类、原始/可见边界不变。内部锚点只取其直接原始子节点：同包唯一完整资源ID、明确启用、非密码/输入/嵌套滚动节点、完整可见，数量2–64；包含敏感子树的节点排除。标签、文本、描述和时钟不参与进展。
- 前后至少两个共同锚点；所有共同锚点类和尺寸一致，垂直于滚动方向的坐标不变，沿滚动轴等量移动（容差1像素），方向与声明一致，距离至少8像素、至多可见轴长的90%。必须至少一个锚点离开且一个新锚点进入可见区域。
- 两次连续独立后置观察稳定，仍属于同一上下文；锚点身份集合未在本次查找中出现。A→B→A、无移动、反向、只有装饰变化、全部替换而无重叠、重复ID或证据不足均不能授权下一次滚动。此判据证明观察到的方向性内容移动，不证明接近业务目标或列表边界。

锚点与类名只在宿主内存使用；位置/身份集合用每任务HMAC摘要。每次已验证 Scroll 的回执保存封闭 `scrollProof`：前后观察ID、前后位置摘要、结果类别、共同锚点数和距离；未证明、unknown或取消不会生成成功证明。反馈新增有界 `scrollProgress`（已验证次数、声明上限、上次结果），不外发锚点身份、坐标、原始标签或输入值。

每次新决策前必须仍处于上一已验证位置；等待/stale/Handoff 不能重置次数、已见页面或位置约束。可信未派发 stale 不消耗 swipe 次数。达到声明上限但目标未见时以 TASK_SCROLL_LIMIT 停止，不再写；已派发后的未知效果仍停止隔离。原完成谓词不变。

## 验收

真实 Service/XML、trace、上游投影与设备/模型替身覆盖四方向、多次后成功、达到上限、整体预算、重复页面、文字/装饰、反向/不一致移动、重复/缺失/全部替换锚点、容器改变、目标歧义/不安全、已验证位置漂移、stale、升级、取消排干及未知写。每个场景断言确切物理输入、调用次数和回执结果；保存失败日志。

固定普通搜索与单次查找对照仍保持基线行为。最终限定回归、容量、实际退出码及源码摘要一起记录。重复行ID、无稳定直接子节点身份或一次滑动完全换屏的列表可能不被支持；不能以离线通过宣称适配任意 App，更不能据此宣称真实模型质量改善。
