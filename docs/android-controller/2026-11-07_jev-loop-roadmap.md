## 0. 取舍与实际架构

保留原方案中的校准、有限恢复、语义与近期动作反馈、操作候选扩展、类型化输入及升级证据。实施顺序改为：**先固定协议与证据 → 修完成契约 → 补未派发 stale 重决策和升级接缝 → 扩大语义及动作范围 → 各阶段独立准入 → 在通过的范围内学习 Skill。**

类型化搜索路径：调用方提交 search/参数/完成谓词 → 宿主采 UI 树与上下文 → 固定搜索阶段生成候选 → Jev 选候选/wait/escalate → 宿主复采及策略检查 → Tap/Fill 或预声明聚焦/IME/有界查找/初始同窗口 Back → 独立验证。显式主 Agent 升级仅可选当前候选、重观察或停止。`Observe mode=arbitrate` 仍是独立建议通道，不能直接获得执行权。

第二意图当前路径：调用方声明单个 set_toggle 目标与布尔值 → 宿主稳定原始 checked 读回 → 已满足零写完成，或生成唯一 Tap 候选 → Jev 选择/显式升级 → 复采及写前检查 → 一次点击 → 同窗口两次稳定读回与最终核验。策略独立为 toggle-v1，搜索版本不变。

通用路径：调用方声明目标、具名输入、包/操作白名单与完成谓词 → 宿主按当前控件证据生成绑定动作和参数引用的候选 → Jev 选择 → 宿主复采/执行/验证 → 自主导航、只读算法等待、有界重新决策或显式升级。正常路径中间主模型调用为零；升级路径单独计数。v19 升级回调已接入现有宿主和上游投影，返回停止码本身不构成升级闭环；截图模型输入与跨调用持久恢复仍未实现。

**结构选择。** 共用三种 decision 的完成谓词、预存检查和完成等待；候选生成、模型响应校验继续独立。恢复接入现有执行器，复用 `task-port`、`step-runtime`、全局 Jev 与设备租约。只有现有职责确有冲突才提取模块，不为每个 J 阶段新增服务容器、锁或通用 Agent 框架。

## 1. 横切契约

- 完成由宿主独立谓词证明；模型 DONE、高概率、ACK 或无异常退出不证明业务成功。
- 保留设备/包/上下文、epoch/TTL、派发前复核、读写策略、原子回执、unknown 禁重放与 owner 隔离。任何检查范围变化必须有独立证据和新策略版本，不能靠删除检查降低 stale 率。
- 每次模型传输仍 `maxRetries:0`；新观察上的新决策计作新的模型调用，不能伪装成零成本重试。不对同一证据重复抽样直到高分。
- 总截止覆盖观察、模型、等待、验证、升级和执行；到期停止接收新动作，在途依赖未排干仍保留租约或隔离。新增恢复/升级计数先放策略内部，只有独立配置确有价值才扩公共预算 schema。
- 本系列自动输入拒绝密码字段。模型输入、持久轨迹、离线夹具分别审查字段：文本框遮蔽与 120 字符截断不等于所有屏幕标签已脱敏。
- 原始输入、屏幕全文、凭据和模型自由输出不进入生产任务轨迹。参数由宿主保存为运行时引用；模型不能修改任务权限、输入或完成谓词。
- 每阶段先固定范围、预算、检查器和验收规则，再做离线及对应真实任务验收。已有动作单 ROM 准入不能自动覆盖新的任务组合。

### J0 — 协议、证据与分阶段校准

**J0.1 协议先行，J0.2 真实校准随候选版本进行。** 不把真实校准设为完成契约修复、离线恢复实现的前置；也不让 J2/J3 改变模型输入和候选空间后继续沿用旧版校准标记。stale、环境故障和决策错误都保留在端到端分母中，分类归因而不是删除所谓“污染样本”。

1. 冻结真实任务、App/ROM/起始状态、输入、独立检查器、代码摘要、候选/提示/词表/完成策略版本、请求与返回模型版本、预算，以及校准集和独立验收集。正常路径、恢复路径、升级路径分开报告。
2. 补齐白名单轨迹：有限概率摘要及拒绝原因、模型请求/返回版本、请求耗时、usage、计数、参数引用、候选和回执关联。值缺失标未知；不臆造成本或回填旧轨迹。新增事件后同步检查 `traceEventLimit`、字节上限和终止预留。
3. 对照 rules、原 Jev 基线和每个候选版本；统一输入、完成检查器及起始状态。无法公平绑定 rules 目标的任务单列，不混入配对结论。保留随机/预先固定顺序、加载与重置耗时、失败和未跑项。
4. 少量任务先作可行性与校准探索，不承诺 `N≥30` 即可推广。阈值只能在校准集确定；独立集只评分，暴露后调参需换新的独立集。`calibrated:true` 绑定明确任务/模型/策略范围，不是全局质量开关。
5. 误派发、误报完成、独立成功、unknown、拒绝、升级各自设分母与门槛。拒绝率不是单独优化目标，不能靠降低拒绝提高危险派发。新意图与不同难度任务不要求机械地“通过率 ≥ 搜索基线”，而应预注册自己的成功与风险判据。

**统计边界。** 30 个独立样本即使零误派发，单侧 95% 二项上界仍约 9.5%；它不能证明误派发率低于 2%。在独立同分布且零失败假设下，需要至少 149 个样本才能让该上界低于 2%；重复同一任务通常相关，也不能直接套这个样本量。协议必须说明按任务还是按动作计风险、样本独立性、置信区间和任务族覆盖；样本不足维持未校准，不为置 true 放宽门槛。

### J1 — 完成契约与有界观察恢复

**J1.1 完成判定统一（已实现；验收档位见 README）。** `search-completion-v2` 与 Jev 候选策略分开记录，未校准状态不变。J0.1 的模型标识、usage、概率摘要与拒绝原因已补最小白名单。

- 三种 decision 共用原始树证据与完整谓词。有 `item` 时，唯一可见容器、条目数量、可选输入匹配及 `absent` 全部成立才算预存成功；空容器不拒绝。仅 ID 的旧契约仍保守拒绝预存标记。entry 后置检查也同步，不能继续单凭结果 ID 判失败。
- 提交后容器可见只是中间证据；完整谓词在同一个局部窗口轮询。最多 5 秒，并受原任务时间/观察预算约束；从提交尝试进入设备执行前起计，包含最后复核及输入耗时，容器与条目等待不各重置 5 秒。已派发提交不重试，超时只读失败；rules 有可信未派发证明的既有重试可建立新尝试窗口。
- 首个修复版本共用 rules 的保守基线：完整谓词成立，至少相隔 200ms 的连续两次完整采样整页摘要与可信上下文一致。这样修复单次 Jev 验证差异，但不声称已经解决动态页面。
- 目标范围稳定或谓词连续成立作为后续独立策略。依据 `targetDigest/outsideDigest/contextDiff` 和 [v6 准入条件](2026-11-06_m5-context-diff-report.md) 选择；包含容器外 `absent` 等全部依赖。窗口/前台/锁屏变化不能用局部摘要忽略；另立策略和批次，不回改旧失败。

**J1.2 只对可信未派发 stale 重新决策（已实现；验收档位见 README）。** `search-v2` 使用 task-port 内部来源证明及原子回执，恢复后也不允许重建上下文基线。

| 情况 | 处理 | 不能做的推断 |
| --- | --- | --- |
| 模型返回后观察变化，尚未进入动作派发 | 丢弃回答/候选；同租约内重新观察、生成候选、请求 Jev | 不能复用旧候选 ID 或仅重复旧动作 |
| 最后派发检查拒绝 | 必须有可信子回执证明未派发，并命中明确 stale 白名单，才允许上述流程 | `TASK_*` 错误名、缺回执或后来页面正常均不足以证明未派发 |
| 模型超时/网络错误/非法分布/低置信度 | 零写停止或显式升级；依赖未排干继续持有所有权 | `TASK_JEV_TIMEOUT` 不是观察过期，不纳入 stale 重试 |
| 动作后验证失败、传输未知 | 停止新写；保留回执，传输未知沿原链隔离/排干 | 不因 settle 超时或高概率建议而回放、Back、重填或重交 |
| 策略拒绝、包/设备/窗口/身份不明、取消、截止 | 硬停止 | 不能把安全边界错误重命名成恢复事件 |

首个恢复策略沿用原总预算，连续第 3 次 stale 终止（最多两次额外重决策），只在独立验证前进后清零连续计数。每次重新决策仍消耗原轮数、模型和观察额度；不重置总截止，不另造无限 recovery 循环。记录逻辑步骤、决策尝试、派发次数和已验证进度，避免未派发失败先消耗“已执行目标”集合。当前动作计数语义若调整，须同步预算/轨迹/测试，不能只修改显示数字。

**J1.3 加载等待与进度（声明标记首批已实现；验收档位见 README）。**

`search-v3` 允许调用方声明同包 `loading.id`，原始树证明唯一可见、非输入/密码且不可点击后才提供加载等待资格。无标签标记可以来自原始树，不依赖展示层保留；未声明或普通候选缺失不能获准。最多两个五秒窗口、200ms采样，标记消失且合法候选出现才结束；仍共享原轮数/模型/观察/总截止，等待不重置 stale 和上下文。循环键使用阶段/候选身份，原始整页摘要仍用于派发新鲜度与最终完成检查。具体契约和夹具见 [本批记录](2026-11-07_jev-wait-escalation.md)。

有可核验的加载证据或已声明目标暂缺时，允许有界只读轮询；普通候选缺失不自动归为加载。完整等待谓词与页面稳定是两件事，不能拿 `waitForIdle` 成功当作加载完成。没有完整证据时停止/升级，已派发步骤不重试。首个完成/stale 修复仍保留旧 `wait` 次数和时长；如改为自适应加载等待，另立版本并固定局部窗口、最大等待次数、采样间隔及总预算。

循环检测保留阶段、相关语义状态、动作目标与已验证前后条件；不能因外部时钟变化认定进度，也不能恢复时清空历史。已派发同一动作不能单纯提高 `maxStuckRounds` 后再试；同 ID 在不同阶段是否可重用必须有独立进度证明。

**Gate。** 空容器/旧结果/延迟条目/结果闪现/条目不匹配/容器外负向条件、模型期间 stale、最后派发 stale、两次恢复后成功、第三次连续失败、取消、超时、预算耗尽和真实传输替身 unknown 全覆盖。断言具体动作次数、目标、原子回执、完成证据与排干边界，不能只断言“恢复或停止”两态。

<a id="J2"></a>

### J2 — 最小语义、进度反馈与决策协议

本批实现与边界见 [冻结契约](2026-11-07_jev-j2-contract.md)；验收档位与数字统一见 README。优先级1–5以封闭语义和现有单问协议落地；第6项采用原等待/stale/升级路由反馈，不另追加仲裁调用。

1. 先让模型能区分候选：封闭语义标签、角色/结构关系、来源类别、近期已验证动作及失败类别、剩余预算。固定数量/长度上限；`screenChanged` 只作辅助证据。中性 ID 仍无法区分就升级，不虚构语义。
2. 搜索词表与结构规则版本化，但不为版本化先建通用配置框架；保留当前明确匹配语义。模糊匹配、新意图及新的模型外发字段均是单独的质量/隐私变更。
3. 原始 label 即使不在文本框里，也可能含联系人、订单、聊天或查询值；`[redacted input]` 加长度截断不是匿名化。默认沿用参数值与屏幕原文不外发契约；确需短标签时单列最小字段、敏感来源处理及任务适用范围，并验证实际请求体。arbitrate 的旧外发边界不能自动套给 RunTask。
4. **优先使用现有单问联合候选**：每个候选已绑定操作、当前目标、输入引用和后置条件。多头 operation/target 仅在明确需要且对照有收益时采用；只消费所选操作兼容的目标头，校验分布、目标集合、输入引用与动作约束。
5. **删除“边缘概率乘积证明联合一致性”。** 没有独立性或条件分布契约时，两个边缘分布相乘不能推导联合正确率。分支兼容性由宿主结构验证，置信阈值按新的协议校准；不能用臆造的联合概率放行动作。
6. page/recovery 仲裁可以为循环提供路由建议，沿用同一观察、模型预算与取消信号；不自动追加模型调用，不发明授权。`continue/reobserve` 只能触发宿主重新验证；加载、完成、补偿仍按 J1/J5 的独立证据处理。

**Gate。** 候选缺语义、屏幕指令注入、敏感 label、非法/缺失/未选分支、输入引用越界、旧观察引用均覆盖；比较独立成功、误派发、升级/拒绝和调用成本，不能只用拒绝率不恶化判通过。改变模型输入或候选空间后，旧阈值保留为暂定值并重新走 J0.2。

### J3 — 按任务族扩展操作候选

设备已有原语只说明可复用执行通道，不等于新决策能力已经验收。真实命令、权限、焦点和后置条件须逐项映射，不能统称“都是 M1.5 接线”。

| 批次 | 候选与实现边界 | 必须证明 |
| --- | --- | --- |
| J3.1 同包搜索 | 已接入 Tap 聚焦、单次 Scroll/host ScrollUntil、ImeAction enter/search 及显式 maxSwipes 的有界多屏 Scroll；使用同一原子执行链，见[首批契约](2026-11-07_jev-j31-contract.md)和[多屏契约](2026-11-07_jev-multiscroll-contract.md) | 新动作显式声明；唯一输入框/焦点与精确读回；多屏每次新观察/决策/原子写，指定目标出现或独立方向性锚点移动证明；回访/漂移/unknown停止，交还不重置次数，原预算不扩大。仍需真实App/模型联合准入 |
| J3.2 导航与新意图 | J3.2a 已接入显式声明的初始同窗口 KeyEvent back，见[契约](2026-11-07_jev-j32-back-contract.md)；LaunchApp、跨 Activity 导航和必要 LongPress 仍未实现 | Back 只用于已知非编辑面板，原始树拒绝输入/密码/可修改选项；来源消失与指定搜索目标稳定出现才前进，不能补偿错误入口。其它导航须独立冻结前后身份、效果和权限边界 |
| J3.3 第二意图 | J3.3a 已接入单个应用内 set_toggle，见[契约](2026-11-07_jev-j33-toggle-contract.md)和[实现](2026-11-07_jev-j33-toggle-implementation.md)；多部分目标仍未实现 | 唯一安全原始目标、明确 checked 属性与稳定读回；已满足零写零模型，否则最多一次 Tap；同窗口、旧观察不授权、未知写不重放。主 Agent/Handoff 不能改布尔目标；未做持久化/业务效果与真实联合准入 |

跨包启动要求显式包范围和新任务契约，不能从当前单包 search 静默扩大；系统设置如果已有授权的 `System` 精确能力，优先走该能力，不为展示 Jev 绕 GUI。`ScrollUntil` 需要容器和目标，不等于任意方向的一次滑动。无新 RPC 形状可以作为范围约束，但不能作为业务通过判据。

**误操作补偿独立立项。** 首批发现已进入错误页面时升级，不能默认 Back 撤销。将来只有在副作用已独立确定、恢复动作预声明且有可验证前后条件时，才能执行有界补偿；补偿是新的写动作，消耗原动作/时间预算，保留原失败与因果记录。未知写不得凭后来观察或模型意见洗成已知，更不能用补偿绕过隔离。

**Gate。** 每个新增操作/任务族独立定义正确进展、反例和检查器；覆盖错误高置信选择、同目标重用、A→B→A、仅装饰变化、输入丢失、焦点切换、权限弹窗及未知写。第二意图通过只证明该任务族，不等于任意 App 自主规划。

<a id="J4"></a>

### J4 — 类型化多字段输入

**J4a 已接入声明双字段路线查询。** 见[冻结契约](2026-11-07_jev-j4-route-contract.md)与[实现](2026-11-07_jev-j4-route-implementation.md)，当前验收数字统一见 [README](README.md)。宿主固定 origin/destination 参数引用，Jev 选未验证字段，RPC 与原始树双重读回，提交前全量复核；已验证字段丢失硬停。route-v1 独立于 search-v8/toggle-v1，真实联合准入及其它表单类型未做。

先从单 `query` 扩为宿主类型化参数与字段角色绑定，例如起点/终点各有明确参数引用。Jev 可选择字段与合法引用，实际值由宿主复制；每次 Fill 独立精确读回，提交前再次校验相关字段与焦点。凭据、密码和任意自由生成文本不进入该机制。

**精确 span 是可选后续。** span ID 必须有足够的字段语义才能选择；只隐藏值并给出不透明编号，模型无法确定哪个值属于哪个字段。若 goal/候选值本身发给 Jev，就已经改变隐私边界；mobile-jev 正是这样工作，不能宣称值不过模型。优先由调用方提供类型化参数，只有缺少参数化入口且数据外发契约明确时才评估精确 span。保留 NONE、溢出、重复/歧义和缺参数的零写拒绝，不让模型补造个人信息。

**Gate。** 不同字段值、相似候选、错误角色、部分填入后页面变化、精确读回失败、多字段提交完成均有独立场景；验证实际请求和轨迹不泄漏未声明字段。每个多字段任务族走自身 J0.2，不能直接比较搜索任务成功率决定准入。

### J5 — 升级接缝与可复现回归

**J5.1 结构化升级证据（已实现；验收档位见 README）。** `task.escalation` 返回白名单历史快照，独立普通轨迹事件持久化同一结构；权限需重新检查，`continuation=not_authorized`，不构成实际升级或续跑凭据。具体字段与停止边界见 [本批记录](2026-11-07_jev-wait-escalation.md)。 证据包括：任务/步骤身份、原意图及输入引用、固定完成谓词与权限范围、最近已验证进度、停止原因/contextDiff、有限候选摘要、派发/unknown 回执和剩余预算。优先复用现有返回值和宿主轨迹存储；若确需状态查询，使用宿主只读接口，**不新增设备端 RPC**。

回执不能建议“改用 rules 精确重试整个任务”：此前可能已有已验证或未知副作用。规则目标也要绑定新观察、已确认的剩余步骤与原授权；跨调用安全恢复属于 M5.2，taskId 本身不是续跑凭据。缺可恢复证据时明确停止。

**J5.2 显式主 Agent / 人工通道（实现与冻结协议见 [J5.2 契约](2026-11-07_jev-j52-contract.md)，验收档位见 README）。** 将“升级证据”与“实际升级调用”分开交付，后者应在扩大动作/意图前完成相应分支验收：

- 在宿主现有调用链注入有界重规划回调；正常路径零调用，异常路径按预注册上限计主模型调用。首批只允许同一次在途任务、同一租约和总截止内等待；没有回调或预算时停止，不后台偷偷启动主模型。
- 返回声明式建议，重新校验包、动作、参数引用、不可变完成谓词及新观察。扩大业务目标或权限时结束当前执行交回调用方，不由模型自授。回调不得递归调用另一个抢锁的 RunTask；由当前所有者继续执行通过校验的剩余计划。
- 人工分支复用 M4.0 Handoff，拒绝/超时/取消可终止，交还后重新观察和验证；继续按钮不证明业务完成、不批准后续敏感写。
- M4.1 viewer takeover 目前取消并排干原 Agent，不能称为同任务暂停/恢复。需要 viewer 交还后自动续跑时，另接 M4.1/M5.2 所有权移交。
- 不刷新已执行步骤、unknown、总预算或循环历史。主模型/人类回答不能直接解除设备隔离；未知写保持原恢复要求。

**J5.3 回放从早期就建，不等待 J5 最后完成。** [夹具目录](../../tests/fixtures/android-jev/README.md) 已包含空容器、延迟条目、stale、声明等待及 Back 固定场景；统一回放目录 `replay.json` 覆盖 search/toggle/route/ui_task 正常、stale、硬停止、unknown 写与升级通道，并以反事实对照证明判据依赖注入决策（见 [历史首批](2026-11-07_jev-j53-replay-implementation.md)及[v19 扩展](2026-11-07_jev-ui-task-offline-v19.md)）。仍不代表完整轨迹回放。生产脱敏轨迹只有摘要/计数/引用，不能重建完整 UI 或所有未选分支。将它用于预算、派发和停止的证据核对；控制回放使用独立维护的去标识化离线夹具，包含结构、目标关系、环境转移、注入模型回答/错误和独立预期。真实 UI 原文不自动落入 CI 语料，HMAC 也不是可还原教学轨迹。

同一夹具可验证确定性控制行为，固定模型回答不证明真实模型质量；单条历史轨迹只覆盖实际走过的路径，不能冒充反事实分支。夹具版本、来源和变换规则可追溯，修复前失败保留；词表/协议更新时不能只修改注入答案追绿。

**Gate。** 缺服务、一次升级后恢复、无效重规划、超时/取消、回调重复、Handoff 拒绝/交还、viewer 取消全部覆盖；真实主模型次数可计、总预算连续、无重复派发。回放逐条验证预期动作和副作用，不能只检查相同输入得到相同输出。

### J6 — 可选视觉接入

未排期。UI 树无目标时才评估 M3 的 OCR/模板/其他视觉适配器。Jev 当前文本决策通道不能被假定支持图片或 Box；若未来供应商提供该能力，先核对实际 API/模型契约、数据外发、坐标映射、来源身份与新验收集，再立单独候选版本。截图用于人类展示和图片进入模型是两种不同通道。

## 3. 实施依赖与分批范围

```text
J0.1 协议/最小证据 + J5.3 离线夹具
  → J1.1 完成契约统一
  → J1.2 未派发 stale 重决策 + J1.3 等待/进度边界
  → J5.1 升级证据 + J5.2 有界宿主/人工升级
  → J2 最小语义与近期反馈
  → J3.1 同包搜索动作 → J3.2/J3.3 新任务族、J4 多字段
每个候选版本 → 对应的 J0.2 校准与独立验收；不互相继承结论
通过的任务范围 + M5.1b 可追溯轨迹 → M5.1c/d Skill 草稿/复用
已验证 Skill → M5.1e 版本修复；跨调用持久恢复另依赖 M5.2
需要视觉时：M3 → J6；无需先完成所有 J 阶段才研究 M3
```

- J1/J2/J3 依赖所用动作、身份/上下文、策略的对应准入；不要求 M1.5 全部动作通过才修搜索循环。
- J5 的主 Agent 升级属于 M5 宿主编排；人工分支依赖 M4.0。M3 是视觉中间层，不是外层 Agent 闭环，也不要求显示窗口或虚拟屏先完成。
- 最小轨迹随实现同步，不能等执行器写完再补可审计性；完整 Skill 教学轨迹按 M5.1b 的独立字段契约完善，不声称当前摘要已经足够。
- 已通过的搜索范围就可编译 Skill 草稿，不必等待所有意图、跨包或视觉上线；每个 Skill 独立复跑后启用。

## 4. 运行时停止与推广停止

**当前类型化搜索为 search-v9。** 每任务最多 8 轮、2 个最长 5000ms 的声明加载窗口（200ms只读采样）；默认 6 动作/96 图采样/8 模型调用/60000ms，上限 8/256/16/300000ms。Jev 单次请求采用 `jev-request-v2`：读取全局配置（默认 30000ms）并受原任务剩余时间收紧，零传输重试；旧 2000ms 硬截止仅是历史版本。来源为 [策略表](../../modules/services/androidTaskPolicy.js)、[请求适配器](../../modules/services/androidTaskModel.js)、[prepareTask](../../modules/services/androidTaskExecutor.js) 与 [LIMITS](../../modules/services/androidTaskBudget.js)。

**通用 ui-task-v20 独立计预算。** 显式加载或页面未稳定时由宿主算法按五秒窗口只读等待，只消耗原观察预算与总截止，不消耗模型调用；最终 Done 仍须原完整稳定谓词。具体预算由调用者预先冻结，不能借协助刷新。所有任务族主 Agent/Handoff 最长10秒/60秒，包含在原总截止内，正常路径零升级调用；数值上限不代表成功率保证。

| 类别 | 运行时处理 |
| --- | --- |
| 成功 | 宿主完整完成谓词及所选稳定策略成立；只报告声明范围内的 UI 结果 |
| 可恢复观察失配 | 已实现：明确未派发 stale 在原预算内重决策，连续第三次 TASK_STALE_LIMIT；上下文变化仍硬停止 |
| 可等待 | 已实现声明加载标记的有界只读等待；提交后完整完成谓词沿用 J1.1，共享各自局部窗口和原总预算 |
| 需要帮助 | 缺可区分候选、无法证明进度、低置信度、需改变流程；已接 J5 时显式升级，否则停止 |
| 硬停止 | 策略拒绝、设备/身份/上下文不可信、未知写、取消、deadline、预算/循环上限；不借恢复或升级绕过 |

当前回执为 `completed/stopped + code + 原子回执`；Jev停止附J5.1结构化历史证据，显式 Agent/Handoff 已接入同一在途任务，交还后复核；跨调用和 viewer 自动续跑未接入。不要用新的任务终态覆盖原子 unknown，也不要把停止带码包装成已经自动处理完异常。

**推广前冻结验收矩阵。** 完成契约、派发前变化、加载、进度/循环、错误高概率回答、未知写、升级、隐私和轨迹容量均有正反例；模型与设备联合任务另行执行。出现越权、重复写、错误目标继续执行或误报完成，停止该候选版本推广并保留证据；不通过删样本、增轮次、放宽谓词或降低拒绝门槛追绿。

**报告字段。** 保留计划任务总数、成功/失败/unknown/升级/取消/未跑及各分母；恢复成功率以符合恢复条件的任务为分母，同时报告端到端结果。给出候选漏选、误派发、误报完成、Jev/主模型调用数、p50/p95、可获得成本、模型/代码/策略版本。旧真机批次、当前离线测试、新 Jev 联合验收分别记录，不能相互替代。

## 5. 本次修订删改依据

| 原建议 | 修订理由 |
| --- | --- |
| J0 是一切前置，但 J1 又需先做以免污染校准 | 拆成协议/证据先行与逐版本真实校准；保留 stale 在端到端分母中的事实 |
| 30 任务 + 误派发 <2% 即走 calibrated:true | 小样本不能证明该风险上界；另设独立集、统计方法和适用范围 |
| timeout、settle 超时与 stale 统一恢复 | 无法证明未派发，可能重复已发生写；按派发事实分流 |
| operation/target 概率乘积联合对账 | 缺少概率模型依据；改为宿主分支兼容校验或操作已绑定的候选 |
| 脱敏 label 和 span ID 自动保证值不外发 | 截断并非匿名化；参考实现实际发送 goal/候选值；改为明确参数引用与语义字段 |
| 添动作、加 stuck 次数即可自然自修复 | 扩大动作面不能证明补偿正确；优先硬边界与独立进度，补偿另立契约 |
| 真轨迹全部确定性回放，新增只读 RPC 查询 | 摘要无法还原 UI；分离审计轨迹与离线环境夹具，查询属于宿主而非设备 RPC |
| J5 通向 M3，升级一律无自动续跑 | 外层编排属于 M5；允许明确接入的同调用有界续行，跨调用恢复归 M5.2 |
| J6 直接规划 Jev 图片/Box | 当前输入能力不能假定；改为依赖 M3 和真实模型契约的可选接入 |
